# T40: UI Rendering Lifecycle Refactor

*Created: 2026-09-05 21:00:52 IST*
*Last Updated: 2026-09-05 21:24:00 IST*

**Status**: 🔄 **ACTIVE**
**Priority**: HIGH
**Parent**: None
**Dependencies**: T29a, T35d, T35f, T39

## Scope

Repair the demonstrated high-cost UI update paths while preserving the approved
sidebar, Settings, dialogs, menus, updater, and progress presentation.

The work covers incremental Activity updates, targeted Changes updates,
debounced repository refreshes, and persistent progress-modal elements. It is
not a visual redesign, a framework migration, or a replacement of the T39 Git
backend.

## Acceptance Criteria

- [ ] Opening Activity loads retained persisted history once; a live entry does
      not reread the persisted log or recreate the full Activity list.
- [ ] Live Activity updates retain bounded history and preserve reading position.
- [ ] Selection and single-file stage/unstage update only affected Changes rows,
      counts, and controls; collapse state and focus survive the update.
- [ ] Vault event bursts produce one bounded repository refresh and routine
      unchanged scans do not trigger expensive Activity reconstruction.
- [ ] Progress updates change existing statistic, phase, bar, and footer nodes
      rather than rebuilding their subtrees.
- [ ] Existing visual layout and user-visible actions remain unchanged unless a
      recorded runtime acceptance issue requires a separate decision.
- [ ] Automated behavioural checks and real Obsidian desktop/mobile timing,
      scroll, focus, and resize evidence are recorded separately.

## Evidence and Decisions

- The Activity panel invalidates its cache for each log event, rereads persisted
  entries, merges them, empties its pane, and recreates retained rows.
- Changes repaints its full active pane for selection and mutation outcomes.
- The progress modal recreates its statistics, phases, and footer on every
  progress update and every elapsed-time tick.
- The source audit found no corresponding high-frequency rebuild problem in
  Settings, updater dialogs, the ignore editor, or commit-row expansion.
- A full UI rewrite is not justified: the issue is concentrated in update
  strategy and event fanout, while the approved presentation remains valid.
