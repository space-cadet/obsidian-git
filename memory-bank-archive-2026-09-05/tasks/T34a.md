# T34a: PAT Validation and Repository-Access Diagnostics

*Created: 2026-08-10 22:34:02 IST*
*Last Updated: 2026-08-11 02:03:27 IST*

**Status**: 🔄 **IN PROGRESS**
**Priority**: HIGH

## Scope

Make HTTPS authentication failures actionable without exposing credentials.
For GitHub remotes, distinguish token rejection, repository-access denial, and
Git smart-HTTP rejection before a clone or local repository exists.

## Acceptance Criteria

- [ ] Normalize the configured GitHub HTTPS URL and safely trim accidental
  credential whitespace without logging secret values.
- [ ] Keep PATs/passwords out of console logs, Notices, exported diagnostics,
  error messages, tests, screenshots, and Memory Bank records.
- [ ] Prevent the plugin's credential-bearing settings/state file from being
  staged or pushed by automatic vault sync.
- [ ] Validate a GitHub token against a read-only account endpoint and return a
  clear invalid/revoked-token result for HTTP 401.
- [ ] Check access to the configured repository independently of the Git smart
  HTTP check and explain missing repository permission.
- [ ] Preserve generic Git-host testing for non-GitHub remotes.
- [ ] Add focused automated coverage for success, rejected token,
  inaccessible repository, and smart-HTTP rejection.
- [ ] Ensure changed credentials and remote settings take effect for every
  subsequent pull, push, clone, and diagnostic operation.
- [ ] Verify on Android using a newly generated token that is never shared in
  chat, source, logs, or the Memory Bank.

## Evidence at Start

- The prior Test Connection defect was repaired: its old path required a local
  `.git` repository and could initialize or clone the vault. The new path uses
  read-only `git.listServerRefs` only.
- The Android app now displays `HTTP Error: 401 Unauthorized` from GitHub.
- An external read-only diagnostic of the supplied token returned HTTP 401 from
  `GET /user`, `GET /repos/space-cadet/typora-notes`, and the Git smart-HTTP
  ref endpoint. No token value was retained.
