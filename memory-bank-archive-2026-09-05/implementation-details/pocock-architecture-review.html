This is an incremental-deepening report, not authorization for a rewrite, fork, or package replacement.

Top recommendation: deepen operation ownership

The coordinator already serializes some calls, but main.ts still wires credential refresh, logging, progress finalization, manager cleanup, and repository outcomes around individual operations.

flowchart LR
        C[commands] --> O[operation module]
        S[sidebar] --> O
        A[auto-sync] --> O
        O --> G[Git work]
        O --> R[observable outcome]

Concentrate admission, cancellation, completion, and repository-state outcomes at one seam while callers express intent. This has the highest leverage across commands, sidebar actions, auto-sync, progress, and unload behavior.

2. Deepen the repository operation module

GitManager is a 2,883-line module spanning transport, progress, initialization, repair, history, status, staging, commit, push, and sync.

Use the deletion test before extracting code. Keep Git rules together where that preserves depth; separate only a coherent cluster whose complexity disappears behind a smaller caller seam.

3. Deepen the sidebar read module

GitSidebarView owns rendering, cache invalidation, remote fallback, generation guards, log loading, and mutation callbacks.

Keep rendering in the view and concentrate status, history, log data, freshness, and invalidation in a testable read module. T29a remains visual-only; T35b owns behavior.

4. Deepen the update transaction

PluginUpdater combines release selection, HTTP, ZIP parsing, vault writes, backup, rollback, and modal presentation.

Put release identity and install/rollback invariants behind one transaction seam, while keeping result presentation outside it. T35e owns the integrity evidence.

src/updater/PluginUpdater.ts · T35e

5. Make the filesystem seam explicit

The adapter combines native desktop reads, Obsidian fallback, path normalization, stale-entry filtering, and write behavior.

First measure whether platform-specific rules can be concentrated without adding pass-through modules. T35d and T36 retain ownership of transport and dependency acceptance.

src/adapters/ObsidianFsAdapter.ts · T35d · T36

Recommended order

  1. Complete operation coordination and explicit repository-state outcomes.
  2. Freeze behavior with conformance and lifecycle tests.
  3. Extract read models and stores with declared lifetimes.
  4. Reassess the GitManager, updater, adapter, and transport seams.
  5. Decide on rewrite versus continuation only after desktop and Android evidence.

A big-bang rewrite is not advised now. Existing behavior, settings, commands, mobile constraints, and release evidence remain the rollback baseline.
