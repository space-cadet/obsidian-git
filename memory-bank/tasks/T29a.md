## Scope

Replace the incremental Git Sync sidebar presentation with one coherent visual
design based on the approved Changes, Commits, and Log mockups. Preserve the
existing Git behavior and make the redesigned presentation usable on desktop,
mobile, and intermediate sidebar widths.

## Decision

The mockups are the visual design specification. This task is a presentation
redesign, not a rewrite of GitManager, authentication, updater, or repository
state behavior. Existing actions remain available even when the mockups make
them visually secondary.

The contextual interaction model delivered by 4292bf9 remains the behavioral
starting point. T29a supersedes its visual treatment where the current
screenshots and mockups differ.

## Acceptance Criteria

- [ ] Changes, Commits, and Log share a consistent visual system for spacing,
  typography, surfaces, borders, controls, and iconography.
- [ ] The repository header presents branch identity, status, settings, and
  refresh in the mockup hierarchy.
- [ ] Changes preserves staging, unstage, bulk actions, per-file menus,
  .gitignore actions, commit entry, pull, push, force push, and More.
- [ ] Commits preserves Local/Remote switching, expandable rows, file details,
  remote fallback, and empty/error states.
- [ ] Log preserves activity display, export, clear, and copy actions.
- [ ] Loading, empty, local-only, error, long-path, and disabled-action states
  have intentional visual treatments.
- [ ] The content area has one clear scroll owner; the Changes action bar stays
  fixed without obscuring the final row.
- [ ] The layout works at the supplied mobile width, desktop sidebar width, and
  an intermediate width without clipping or accidental horizontal scrolling.
- [ ] Existing automated tests and production build continue to pass.
- [ ] Real Obsidian desktop/mobile screenshot acceptance is recorded separately
  from source-level verification.

## Implementation Plan

1. Define the shared sidebar shell, visual tokens, icon treatment, and state
   conventions.
2. Replace the sidebar presentation markup while preserving existing handlers
   and GitManager calls.
3. Rebuild Changes, Commits, and Log styling as one coordinated CSS system.
4. Verify themes, responsive widths, resize behavior, long content, and host
   chrome in real Obsidian.
5. Record before/after evidence and close the visual acceptance gate.

  commit metadata, log entries, and footer controls so ordinary content does
  not render at heading scale. The follow-up uses explicit pixel sizes for the

  too large.

## Follow-up Audit — 2026-09-02 / 2026-09-03
