# T39: KISS Git Backend Rewrite

*Created: 2026-09-04*
*Last Updated: 2026-09-05 18:54:05 IST*
*Status: ACTIVE*
*Priority: HIGH*
*Parent: None*

## Scope

Replace the current coupled GitManager/UI operation path with a small,
platform-neutral Git backend. The backend must be tested independently before
it is connected to the retained Obsidian UI.

## Requirements

- Examine and record the current architecture and latency sources.
- Keep the backend independent of Obsidian UI, DOM, Notices, CSS, and view
  lifecycle code.
- Provide direct operations for repository state, stage, unstage, commit,
  pull, push, sync, clone, initialize, and history.
- Keep PAT authentication available.
- Add GitHub device authorization as an alternative credential source.
- Test the backend with mocked transport and credentials first.
- Test GitHub API and Git smart-HTTP access with a real GitHub-authenticated
  credential before UI integration.
- Connect the backend to the existing UI only after the backend gates pass.
- Preserve the current plugin as the rollback/reference implementation.

## KISS constraints

- No UI rendering or Obsidian imports in the backend.
- No event bus, general-purpose cache, or multi-layer operation framework in
  the new backend unless a demonstrated requirement makes one necessary.
- One direct operation returns one complete result.
- Local status must not wait for remote history comparison unless requested.
- Single-file stage must not perform a whole-repository status scan first.
