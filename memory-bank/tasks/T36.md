## Scope

Evaluate, fork, adapt, publish, and maintain the isomorphic-git dependency as
an independent project-level effort. The fork is intended to support efficient
bulk Git mutations and any Obsidian/mobile compatibility work that cannot be
accepted upstream quickly enough. This is deliberately a top-level task, not a
child of T35.

## Why This Is Independent

The work has its own upstream baseline, API design, license obligations,
release process, package-distribution requirements, compatibility matrix, and
long-term maintenance burden. It affects T29 and T35, but it is not limited to
plugin reliability hardening.

## User-Reported Ignore Regression Plan — 2026-09-03

The installed 1.29.0 implementation contains an `add()` ignore check that
does not first test whether a path is already tracked. The plugin also marks a
path staged after a no-op add, so caller-supplied Stage and Stage-all lists can
claim success incorrectly. The implementation sequence is definite:

1. Run the existing tracked-and-ignored reproduction against official 1.41.9
   with the Obsidian adapter.
2. Keep isomorphic-git as the source of ignore-rule semantics; do not add a
   second parser in the plugin.
3. Route all staging candidates through one policy, reject ignored untracked
   paths with a clear result, preserve tracked paths, and verify the index
   before reporting a successful stage.
4. If 1.41.9 is compatible, upgrade and pin it. If not, implement the smallest
   compatibility guard or fork change and document the upstream delta.
5. Cover individual Stage, Stage all, automatic sync, nested/glob/negated
   rules, ignored directories, tracked-but-ignored files, and deletions on
   both the desktop and Obsidian adapter paths.

## Implementation Result — 2026-09-03

- Official 1.41.9 is compatible with the current adapter and passes the

- The plugin now treats isomorphic-git as the ignore-rule authority while
  adding a staging-boundary guard and index verification for stale/caller-
  supplied paths. No fork was adopted.
- Fork maintenance remains deferred unless real mobile acceptance exposes a
  1.41.9 incompatibility or an upstream behavior gap.
