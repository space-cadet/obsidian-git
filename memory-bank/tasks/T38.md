## Scope

Record the current Obsidian Git product as a user-facing, implementation-
agnostic specification before preparing the rewrite PRD.

The specification covers all current entry points, features, UI regions,
Settings controls, platform behaviour, actual edge cases, and evidence status.
It does not describe current internal ownership, call chains, module
boundaries, or architectural debt.

## Documentation rule

The product specification is the preservation contract for the rewrite. It
describes outcomes and visible behaviour, not how the current implementation
achieves them. The rewrite must start from this contract rather than from the
current code structure.
