## Scope

Serialize repository mutations and make timers, views, progress UI, clone
recovery, cancellation, and plugin unload safe in the presence of asynchronous
operations.

## Acceptance Criteria

- [ ] Only one mutating Git operation can run at a time.
- [ ] Manual, sidebar, command-palette, and auto-sync paths share the same
  coordinator.
- [ ] Refreshes cannot overlap or update detached/stale view state.
- [ ] Plugin unload cancels or invalidates in-flight work and clears progress
  UI and timers.
- [x] Progress UI reports success only on success and failure only on failure.
- [x] An interrupted clone preserves a documented resumable local Git state or
  reports that no recovery state is available; it must not silently discard the
  only partial state.
- [x] Closing or cancelling the progress surface has explicit semantics: hide,
  cancel, or continue in the background, with no false success state.
- [x] A retry can detect and safely continue a prior partial clone without
  deleting the existing `.git` state first.
- [ ] Add concurrency and lifecycle regression tests.

## Newly Recorded Clone-Recovery Issue — 2026-08-12

- The empty-repository path tries `git.clone`, removes `.git` before starting,
  and falls back to `git.fetch` plus a later checkout when clone fails.
- `git.checkout` is the first explicit worktree-writing stage in the fallback
  path. If the operation is interrupted during fetch or pack processing, the
  vault can contain no visible repository files.
- `isomorphic-git` removes its partial git directory when its clone operation
  fails, so the current path is fail-and-restart rather than resumable.
- The progress modal close control only closes the UI; the current HTTP client
  and Git calls do not receive a cancellation signal.
- Ownership: T35b defines operation lifetime, cancellation, retry, and resume;
  T35c defines `.git` replacement and backup safety; T35d defines transport
  telemetry needed to show recovery progress.

## Implementation Slice — 2026-08-12

- Replaced fresh and shallow clone use of `git.clone` with explicit
  `init -> fetch -> checkout`, so isomorphic-git's clone-failure cleanup cannot
  remove the only partial `.git` state.
- Added an `AbortSignal` to the progress handle and HTTP response iterator;
  closing the modal now requests cancellation, and fetch/checkout callbacks
  stop progressing after cancellation.
- Added focused regression coverage proving an interrupted remote request
  retains `.git/HEAD` and `.git/config` for retry. Operation serialization,
  durable retry metadata, and protected replacement backups remain open.
- Added a checkout-pending marker containing the fetched branch tip. A retry
  validates the marker and local commit object, skips fetch when checkout is
  the only incomplete phase, and clears the marker after successful checkout.

## Follow-up Issue — Sidebar read performance and stale refreshes (2026-09-02)

- The sidebar refresh currently repeats branch/status work and performs
  multiple working-tree status scans before rendering Changes.
- Switching Local/Remote commits invokes the complete sidebar refresh instead
  of loading only the selected history source.
- Add a shared immutable read snapshot for header, staged count, and Changes;
  derive detailed status and groups from one matrix where possible.
- Load Commits and Log independently, cache remote history for the session, and
  invalidate it after pull or push.
- Add a view generation or cancellation check so an older refresh cannot update
  detached or newly selected tab content.
- Add regression coverage for scan counts, tab-specific loads, cache
  invalidation, and rapid tab switching.

## Sidebar, Log, and Push Follow-up Plan — 2026-09-03

- First-load blank content is an async render-order defect: the view clears its
  content before repository reads finish and has no loading state. Render the
  shell immediately, retain the last successful snapshot, and guard every
  response with a view generation.
- Ahead/behind errors currently collapse to zero and render "Up to date". Keep
  comparison errors and expose explicit up-to-date, push, pull, diverged, and
  unavailable states; distinguish local and remote commit provenance.
- Tab switches rebuild the DOM and repeat reads. Add independent session
  caches for status, local/remote history, details, and activity logs, with
  precise invalidation after mutations.
- The Log tab currently reads only the in-memory logger. Load bounded entries
  from the persistent file logger, merge and deduplicate them, and make clear,
  export, and retention share one store.
- Memory metrics are sampled by an unconditional ten-second timer. Make
  sampling opt-in, stop it when diagnostics are off or the plugin unloads, and
  bound retention.
- Push uses clone phases and response-consumption bytes, so a quiet request
  appears stuck at Fetching. Give push its own phases, an independent elapsed
  timer, honest indeterminate transfer state, and a persistent success result
  that the user dismisses.

These are separate tests over shared lifecycle and observability services. The
`.gitignore` staging-boundary fix is implemented and tracked with T35b, T35d,
and T36; broader mobile and nested-rule acceptance remains open.

## Sidebar History and Single-File Staging — 2026-09-04

- Direct `stageFile()` no longer calls a repository-wide `statusMatrix()`. It
  reads the tracked-path list once, stats only the requested worktree path,
  and uses `remove()` for a tracked deletion before adding normal files.
- Bulk `addAll()` retains its shared status snapshot and final index-state
  verification; this optimization is limited to the slow single-file path
  reported by the user.
- The Log view now renders all entries retained by the logger/file logger
  instead of hiding everything beyond the newest 50 rows. Persistent history
  remains bounded by the configured diagnostic retention setting.
- The Local/Remote commit-source control is now sticky within the sidebar
  scroll owner, so it remains usable while the selected commit list moves.
- After a single-file mutation completes, the Changes view now repaints from
  the updated snapshot directly. It no longer starts a second repository-wide
  refresh before showing the staged/unstaged transition.
- Bulk Stage all and Unstage all now use the same direct repaint path. Stage all
  moves only successful files; Unstage all reports per-file failures so a
  partial operation is not displayed as complete.
- Full verification passes with 72 Node tests, production build, artifact
  identity, 10 isomorphic-git checks, and `git diff --check`. Real Obsidian
  timing and visual acceptance remain open.
