# T35b: Operation Coordination and Lifecycle Safety

*Created: 2026-08-11 02:03 IST*
*Last Updated: 2026-08-12 13:59:20 IST*

**Status**: 🔄 **IN PROGRESS**
**Priority**: HIGH
**Parent**: T35

## Scope

Serialize repository mutations and make timers, views, progress UI, clone
recovery, cancellation, and plugin unload safe in the presence of asynchronous
operations.

## Acceptance Criteria

- [ ] Only one mutating Git operation can run at a time.
- [ ] Manual, sidebar, command-palette, and auto-sync paths share the same
  coordinator.
- [ ] Refreshes cannot overlap or update detached/stale view state.
- [ ] Plugin unload cancels or invalidates in-flight work and clears progress
  UI and timers.
- [x] Progress UI reports success only on success and failure only on failure.
- [x] An interrupted clone preserves a documented resumable local Git state or
  reports that no recovery state is available; it must not silently discard the
  only partial state.
- [x] Closing or cancelling the progress surface has explicit semantics: hide,
  cancel, or continue in the background, with no false success state.
- [x] A retry can detect and safely continue a prior partial clone without
  deleting the existing `.git` state first.
- [ ] Add concurrency and lifecycle regression tests.

## Newly Recorded Clone-Recovery Issue — 2026-08-12

- The empty-repository path tries `git.clone`, removes `.git` before starting,
  and falls back to `git.fetch` plus a later checkout when clone fails.
- `git.checkout` is the first explicit worktree-writing stage in the fallback
  path. If the operation is interrupted during fetch or pack processing, the
  vault can contain no visible repository files.
- `isomorphic-git` removes its partial git directory when its clone operation
  fails, so the current path is fail-and-restart rather than resumable.
- The progress modal close control only closes the UI; the current HTTP client
  and Git calls do not receive a cancellation signal.
- Ownership: T35b defines operation lifetime, cancellation, retry, and resume;
  T35c defines `.git` replacement and backup safety; T35d defines transport
  telemetry needed to show recovery progress.

## Implementation Slice — 2026-08-12

- Replaced fresh and shallow clone use of `git.clone` with explicit
  `init -> fetch -> checkout`, so isomorphic-git's clone-failure cleanup cannot
  remove the only partial `.git` state.
- Added an `AbortSignal` to the progress handle and HTTP response iterator;
  closing the modal now requests cancellation, and fetch/checkout callbacks
  stop progressing after cancellation.
- Added focused regression coverage proving an interrupted remote request
  retains `.git/HEAD` and `.git/config` for retry. Operation serialization,
  durable retry metadata, and protected replacement backups remain open.
- Added a checkout-pending marker containing the fetched branch tip. A retry
  validates the marker and local commit object, skips fetch when checkout is
  the only incomplete phase, and clears the marker after successful checkout.
