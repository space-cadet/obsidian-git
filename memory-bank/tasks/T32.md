## Details

Addressed three user-reported issues from mobile testing:
1. Obsidian crashes when pulling large repos (100MB+) on mobile
2. Remote commits should be viewable even without local repo initialization
3. Need progress display and debug logs for troubleshooting

## Problems Identified

1. **Mobile crash on pull** — `git.pull()` on an empty repo fetches the entire remote history, causing memory exhaustion in the mobile WebView. isomorphic-git keeps pack files in memory.

2. **Remote commits invisible without local repo** — `git.log({ ref: 'origin/branch' })` requires a local git repo with fetched refs. Before initialization, no commits are visible.

3. **Silent operations** — Clone/pull/push show only a spinner with no progress info. Users can't tell if the app is hanging or working.

4. **No crash diagnostics** — When Obsidian crashes, logs are lost. No way to understand what caused it.

## Solutions Implemented

### 1. GitHub API Fallback for Remote Commits

**File**: `src/gitManager.ts`

- Added `fetchRemoteCommitsViaApi()` — private instance method
- Added `static fetchRemoteCommitsFromGitHub()` — static method for use without GitManager instance
- Parses repo URL to extract `owner/repo` (supports HTTPS and SSH formats)
- Uses GitHub REST API: `GET /repos/{owner}/${repo}/commits?sha=${branch}&per_page=20`
- Authenticates with PAT as `Bearer` token
- Returns same `GitCommit[]` format as `git.log()`

**File**: `src/views/GitSidebarView.ts`

- `renderCommitsTab()` now handles `gitManager === null`:
  - Local mode: shows "No local repository — initialize or clone"
  - Remote mode: tries `gitManager.getRemoteLog()` first, then falls back to `GitManager.fetchRemoteCommitsFromGitHub()` via dynamic import
- Works even before any repo initialization — user can see remote history and decide to clone

### 2. Progress Tracking During Operations

**File**: `src/gitManager.ts`

- Added `GitProgressEmitter` class — simple EventEmitter-compatible object for isomorphic-git
- Added `createProgressNotice()` helper — returns `[onProgress, hideNotice]`:
  - Creates persistent Notice with operation message
  - Updates with phase name (e.g., "Counting objects", "Receiving objects")
  - Shows percentage and KB transferred when available
  - Hides automatically on success or error
- Integrated into:
  - `pull()` — "Pulling from remote"
  - `shallowFetchAndCheckout()` — "Fetching remote files"
  - `cloneRepository()` — "Cloning ${branch}"
  - `push()` — "Pushing to remote"

**User experience**: Instead of a silent spinner, user sees:
> "Pulling from remote — Receiving objects (45%, 12KB / 27KB)"

### 3. Debug Log Export

**File**: `src/logger.ts`

- Added `exportToFile(vault, filename?)` method:
  - Writes all in-memory log entries to a markdown file
  - Includes timestamp, log level, namespace, message, and JSON data
  - Uses emoji indicators: 🔴 error, ⚠️ warn, 🔍 debug, ℹ️ info
  - File path: `.obsidian/plugins/obsidian-git-sync/debug-log-{timestamp}.md`

**File**: `src/main.ts`

- Added command: `git-sync-export-logs` — "Export debug logs"
- Accessible from command palette

### 4. Shallow Fetch for Empty Repos (Crash Prevention)

**File**: `src/gitManager.ts`

- Added `hasLocalCommits()` — checks if `git.log({ ref: 'HEAD', depth: 1 })` returns any commits
- Modified `pull()`:
  - Before pulling, checks `hasLocalCommits()`
  - If no local commits, calls `shallowFetchAndCheckout()` instead of `git.pull()`
- Added `shallowFetchAndCheckout()`:
  - `git.fetch({ depth: 1, singleBranch: true })` — only downloads latest commit
  - `git.resolveRef()` to get the fetched commit OID
  - `git.writeRef()` to create local branch at that OID
  - `git.checkout()` to write files to working tree
- Modified `initializeRepo()` to use `cloneRepository()` (which also uses depth: 1 + progress)

**Why this prevents crashes**: 
- `git.pull()` on empty repo fetches ALL refs and objects from remote
- `git.fetch({ depth: 1 })` only downloads the single latest commit
- For a 100MB repo with 500 commits, this reduces download from 100MB+ to ~200KB-2MB
