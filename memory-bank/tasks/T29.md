## Details
Build an Obsidian plugin for git synchronization using isomorphic-git (pure JS, no native git binary). Supports desktop (Electron) and mobile (iOS/Android). Features: three-tab sidebar (Changes, Commits, Git Log), auto-sync, file staging, push/pull with credentials.

## Approved Sidebar UX Design — 2026-08-18

The user approved the sidebar mockups in `memory-bank/assets/ui-mockups/`.
They remain the governing visual specification for T29a. The interaction
model below was implemented in `4292bf9`; T29a now records the full visual
redesign needed to bring the sidebar presentation into line with the mockups.

- The Changes tab is the action-oriented tab. It keeps a compact bottom bar
  with `Commit (N)`, `Pull`, `Push`, and `More`.
- Commit message entry is opened from `Commit (N)` in a modal instead of
  permanently occupying the bottom of the sidebar.
- `.gitignore` editing and ignored-pattern management are available from
  `More`, rather than being permanently visible above the file lists.
- Force push remains available from `More` and keeps its confirmation step.
- The Changes tab keeps explicit `Stage all` and `Unstage all` labels so the
  bulk action is understandable without decoding symbols.
- Per-file secondary actions are behind a `…` menu; the primary stage or
  unstage action remains visible on each row.
- Refresh belongs in the branch header and is available on every tab.
- Commits and Log use the full available height and do not show the Changes
  tab action footer.
- Log has a compact `More` menu for exporting, clearing, and copying details.

## Follow-up Audit — 2026-09-02

The updater repair and sidebar review identified additional work that remains
open. These follow-ups are assigned to the existing T29a, T30, T35b, T35c,
T35e, and T35f ownership rather than creating duplicate top-level tasks.

- Build listings should display the commit subject for each build and avoid
  showing the full SHA in release titles. Older releases without a subject can
  use a cached commit lookup as a fallback.
- The sidebar header and Commits Local/Remote selector need compact density
  options. The source currently has no separate branch-selection control;
  branch switching remains the distinct backlogged T31 scope.
- Changes loading repeats repository status scans, and Local/Remote switching
  performs a full sidebar refresh. A shared read snapshot and tab-specific
  loading are needed, with stale refresh responses discarded.
- Remote commit browsing must remain available when the configured remote is
  usable but the local `.git` directory is missing or damaged.
- Repairing a damaged repository needs a separate, recoverable rebuild path
  that compares remote content with current vault files before replacement.
- Regression coverage is needed for metadata display, refresh call counts,
  remote-only browsing, damaged repositories, and repair conflict previews.

## Decisions Made
- **isomorphic-git over native git**: Cross-platform compatibility ✅
- **ObsidianFsAdapter over LightningFS**: Delegates to `app.vault.adapter` ✅
- **Node.js fs fallback**: `window.require('fs')` for pack index files on desktop ✅
- **Lazy git manager init**: Only created when sidebar opens or sync command runs ✅
- **Refresh interval 0 = disabled**: No auto-refresh when set to 0 ✅
- **Local-only mode**: Skip push/pull when no repo URL configured ✅
- **PAT auth**: Any username works with fine-grained PATs ✅
- **No conditional UI hiding**: All controls were previously always visible;
  superseded by the approved tab-specific action layout below ✅
- **Sidebar actions are tab-specific**: Changes owns the compact commit/sync
  footer; Commits and Log use the full content height ✅
- **Commit message is on demand**: Open a commit modal from `Commit (N)` ✅
- **Secondary controls use menus**: `.gitignore`, force push, file ignore, and
  log utilities are grouped under `More` ✅
- **Bulk labels are explicit**: Use `Stage all` and `Unstage all` in the
  section headers ✅
- **Dev releases on every push**: `dev` tag auto-updated, pre-release, not latest ✅
- **Updater uses Obsidian APIs**: `requestUrl` and `vault.adapter` keep release checks and installation desktop/mobile compatible ✅
- **Dev updater identity**: Compare the embedded build commit hash with `main` HEAD for rolling `dev` releases ✅
- **Archive layout**: Copy unpacked plugin files to `dist/` directly and retain the versioned ZIP ✅
- **Hardening boundary**: T35 owns shared reliability, security, lifecycle, transport, updater, and CI improvements; T29 retains release packaging and acceptance ownership ✅
