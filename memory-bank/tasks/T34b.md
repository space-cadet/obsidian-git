# T34b: GitHub Device-Flow Authentication

*Created: 2026-08-10 22:34:02 IST*
*Last Updated: 2026-08-11 02:31:07 IST*

**Status**: ⏸️ **PLANNED**
**Priority**: MEDIUM
**Parent**: T34

## Scope

Offer an opt-in GitHub device-authorization sign-in from the plugin Settings
screen. The flow must work on Android and desktop without a local callback
server and must continue to use the existing HTTPS Git transport after token
acquisition.

## Planned Requirements

- Register and configure a narrowly permissioned GitHub App with device flow.
- Show a user code, verification URL, cancel state, expiry state, and
  completion state without exposing access or refresh tokens in notices/logs.
- Store the resulting credential through Obsidian `SecretStorage`; keep only a
  secret reference in plugin settings and document that each device must link
  its own secret. Do not use standard plugin data as a plaintext fallback.
- Support sign-out, expired-token recovery, and a fallback manual PAT path.
- Keep non-GitHub remotes on their existing manual credential workflow.
