## Description

Staging a deleted file through the Changes panel threw `NotFoundError`
because `git.add` lstats the workdir path before staging, and deleted
files have no workdir entry. A single deleted row also poisoned
Stage-all and Stage-selected batches.

## Acceptance Criteria

- [x] Stage on a "Deleted" row stages the deletion instead of throwing.
- [x] Stage-all and Stage-selected batches tolerate deleted paths.
- [x] Present files still stage via `git.add`; missing files route to
      `git.remove`.

## Implementation Details

`stageFile` now splits paths by workdir existence: paths that exist go
to `git.add`, paths that do not exist go to `git.remove`, which stages
the deletion. Commit `a0e5705`, `src/repository.ts` (+13/-1).
