## Acceptance Criteria

## Implementation Update

- Added direct HTTP(S) Fetch, fast-forward-only Pull, Push, and Clone flows
  through `isomorphic-git` and the Obsidian `DataAdapter` filesystem bridge.
- Added Changes action-bar actions with clear completion or failure notices.
- Remote operations are serialized, recorded in Activity, and refresh the
  sidebar after successful completion.
- Clone refuses a non-empty vault-relative destination; Pull does not attempt
  conflict resolution in this KISS increment.

Source implementation is complete for T7c/T7d. The user verified the pushed
remote workflow, including the Changes toolbar Pull and Push actions.

## Failure Evidence Update

- Pull now passes the configured commit author and committer because
  `isomorphic-git` requires an identity even for the fast-forward-only path.
- The Obsidian HTTP bridge now accepts the array-of-chunks request body used by
  Push, as well as async iterator bodies, and returns an async-iterable response.
- The user-provided Log evidence identified both failures: `MissingNameError`
  from Pull and `body.next is not a function` from Push.

## Next Refinements

- Add progress modals and richer Git-style result messages.
- Exercise non-fast-forward, divergence, authentication, empty-repository, and
  clone edge cases separately.

## KISS Boundary

Implement one direct authentication and transport path before adding
alternatives or automated recovery.
