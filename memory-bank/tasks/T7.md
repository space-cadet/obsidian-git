# T7: Multi-Repo Support (Repos in Subfolders)

*Created: 2026-05-30 23:25:00 IST*
*Last Updated: 2026-05-30 23:25:00 IST*

**Status**: 🆕 **NEW**
**Priority**: MEDIUM

## Details
Currently the plugin assumes a single git repo at the vault root. Users may want to sync individual folders as separate repos — e.g., a `projects/` folder with its own git history, or a `blog/` folder separate from the main vault.

## Use Cases
1. **Vault root repo** — Current behavior, sync entire vault
2. **Subfolder repo** — e.g., `projects/my-paper/` has its own `.git`
3. **Multiple repos** — Vault root + several subfolders each with their own repo
4. **Selective sync** — Only sync certain folders, not the entire vault

## Features Needed

### Repo Detection
- **Auto-detect** — Walk vault and find all `.git` directories
- **Manual add** — User specifies folder path in settings
- **Repo list** — Display all detected repos with name, path, branch

### Per-Repo Settings
Each repo needs its own:
- Remote URL
- Branch name
- Auth credentials (or shared)
- Auto-sync interval (or global)
- Commit message template

### UI Changes
- **Repo selector** — Dropdown in settings and sidebar to switch active repo
- **Per-repo status** — Sidebar shows status for selected repo
- **Bulk operations** — "Sync all repos" button

### Data Structure
```typescript
interface RepoConfig {
  id: string;           // unique identifier
  name: string;         // display name (e.g., "My Paper")
  path: string;         // relative to vault root (e.g., "projects/my-paper")
  repoUrl: string;
  branchName: string;
  autoSyncInterval: number;
  autoCommitMessage: string;
}

// Settings update
interface GitSyncSettings {
  repos: RepoConfig[];  // replaces single repoUrl/branchName
  activeRepoId: string; // which repo is currently selected
  sharedCredentials: boolean; // use same auth for all repos
  username: string;     // shared
  password: string;     // shared
  author: { name: string; email: string }; // shared
}
```

## Technical Approach

### GitManager Per Repo
Instead of single `this.gitManager`, have a map:
```typescript
this.gitManagers: Map<string, GitManager> = new Map();

// Initialize for each repo
for (const repo of this.settings.repos) {
  const fs = new FS(repo.id); // separate IndexedDB per repo
  const gitManager = new GitManager(fs, repo.path, credentials, statusBar);
  this.gitManagers.set(repo.id, gitManager);
}
```

### LightningFS Namespacing
Each repo needs its own filesystem to avoid conflicts:
```typescript
const fs = new FS(`obsidian-git-${repoId}`);
// This creates separate IndexedDB databases
```

### Vault Adapter Consideration
If using Obsidian's `Vault.adapter` (instead of LightningFS):
- Each repo path needs its own `dir` parameter for git operations
- `git.statusMatrix({ fs, dir: repoPath })`
- `git.log({ fs, dir: repoPath })`

### Migration
- **Old settings** (single repo at root) → auto-migrate to new `repos` array
- Keep backward compatibility for existing users
