# T30: Remote Commits View — Parallel Local/Remote History Display

*Created: 2026-06-01*
*Last Updated: 2026-09-03 02:37:37 IST*

**Status**: ✅ **COMPLETED**
**Priority**: MEDIUM
**Parent**: T29 (obsidian-git Plugin)

## Scope

Display remote commit history alongside local commits in the sidebar. Currently the plugin shows "ahead/behind" counts but not the actual commits from the remote. This feature adds a split-pane or toggle view in the History/Log tab that fetches and displays remote commits for comparison.

## Motivation

- User currently sees "2 ahead / 1 behind" but has no visibility into what those remote commits are
- Useful for deciding whether to pull (see what you'd get) or force push (see what you'd overwrite)
- Natural extension of existing ahead/behind indicator — gives it meaning beyond just numbers

## Design

### UI Approach

**Option A: Split-pane History tab**
- Top half: Local commits (existing)
- Bottom half: Remote commits (new)
- Visual indicator on each commit showing its origin (local vs remote)
- Common commits merged into a single timeline with arrows showing divergence

**Option B: Toggle in existing History tab**
- "Local" / "Remote" toggle buttons at top of History tab
- Default shows local; clicking "Remote" fetches and displays remote log
- Simpler implementation, less UI real estate

**Decision**: Start with **Option B** (toggle) — simpler, less risk, can evolve to Option A if needed.

### Data Flow

1. On toggle to "Remote" view:
   - Call `git.fetch({ fs, http, dir, remote: 'origin' })` to get latest refs
   - Call `git.log({ fs, dir, ref: 'origin/main' })` to get remote commit history
   - Render in same list format as local commits
2. Cache remote log for session (don't re-fetch on every toggle)
3. Auto-refresh remote view when user pulls/pushes

### Edge Cases

- No remote configured → toggle disabled with tooltip
- Remote unreachable → show error inline, don't crash
- Empty remote (no commits) → show "No commits on remote yet"
- Divergent histories (no common ancestor) → show both sides with warning

## Technical Notes

- isomorphic-git supports `git.fetch()` and `git.log({ ref: 'origin/main' })`
- Need to handle auth for fetch (reuse existing GitHttpClient + credentials)
- Commit SHA comparison to detect common commits
- Mobile: fetch is network operation, may be slow — add loading state
