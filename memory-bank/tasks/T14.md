## Refactoring Plan

```text
Current: GitSyncView
  +-- view lifecycle and background refresh
  +-- repository refresh and Changes reconciliation
  +-- Changes UI, selection events, and file actions
  +-- commit-history reads, cache, and paging

Planned:
  GitSyncView
    +-- CommitHistoryController (history state and reads)
    +-- ChangesPanel (display and callbacks)
    +-- RepositoryRefreshController (repository reads and reconciliation)
    +-- existing selection/snapshot helpers and panel renderers
```

1. **Commit history with T16c:** move local/remote history loading, pagination,
   detail caching, and loading/error state into a `CommitHistoryController`
   when T16c adds repository-scoped history. Keep `CommitHistoryPanel` as the
   renderer; pass repository ID, root, and selected ref explicitly.
2. **Changes display as needed:** move folder-tree, row, filter/sort, and
   focus/scroll rendering into a `ChangesPanel` only when T16/T17 needs a
   distinct presentation owner. Keep Git writes, notices, Activity messages,
   and refresh calls behind explicit callbacks.
3. **Refresh ownership with repository isolation:** extract inspection and
   full/path-scoped reads when T16/T17 needs repository-aware refresh state.
   Preserve generation checks so late results cannot replace a newer selected
   repository. Keep selection pruning in `ChangeSelection` and snapshot
   updates in `ChangeListState`.
4. **Reassess the remaining work:** review background event batching and
   stage/commit actions separately. Move them only if they gain a clear owner
   and focused tests; do not split code solely to reduce line count.
