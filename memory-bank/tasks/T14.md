## Refactoring Plan

```text
Current: GitSyncView
  +-- view lifecycle and background refresh
  +-- repository refresh and Changes reconciliation
  +-- Changes UI, selection events, and file actions
  +-- commit-history reads, cache, and paging

Planned:
  GitSyncView
    +-- CommitHistoryController (history state and reads)
    +-- ChangesPanel (display and callbacks)
    +-- RepositoryRefreshController (repository reads and reconciliation)
    +-- existing selection/snapshot helpers and panel renderers
```

1. **Commit history first:** move local/remote history loading, pagination,
   detail caching, and loading/error state into a `CommitHistoryController`.
   Keep `CommitHistoryPanel` responsible for display and keep the view as the
   Obsidian-facing caller. Pass repository path and branch explicitly; reset
   cached state when either changes.
2. **Changes display next:** move folder-tree, row, filter/sort, and focus/scroll
   rendering into a `ChangesPanel` that receives data and callbacks. Keep Git
   writes, notices, Activity messages, and repository refresh calls in the
   existing owner until the callback contract is clear.
3. **Refresh ownership after that:** extract repository inspection, full or
   path-scoped Changes reads, and snapshot reconciliation into a
   `RepositoryRefreshController`. Preserve generation checks so a late result
   cannot replace newer repository state. Keep selection pruning in
   `ChangeSelection` and pure snapshot updates in `ChangeListState`.
4. **Reassess the remaining work:** review background event batching and
   stage/commit actions separately. Move them only if they gain a clear owner
   and focused tests; do not split code solely to reduce line count.

### Guardrails

- Keep `src/main.ts` callbacks and the integration-provider API stable while
  these internal modules change.
- Keep Git operations in `src/repository.ts` and remote transport in
  `src/remote.ts`.
- Preserve explicit full Changes scans; background and integration updates
  should remain path-scoped when the affected paths are known.
- Add tests for each extracted owner, including repository/branch changes,
  stale async results, and failed operations. Keep installed Obsidian checks
  separate from unit tests and builds.
- Keep this task within the Obsidian Git repository; `server.js` belongs to
  mb-core and is outside its scope.
