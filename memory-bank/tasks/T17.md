## Description

Add lower-priority Git features after the core multi-repository workflows in
[T16](T16.md). Lower priority describes product sequencing, not assumed technical
ease. Every feature remains fully usable on mobile and restricted to repositories
inside the vault. Reuse T16 repository contexts, controls, and mutation coordination.

## Subtasks

All implementation is pending. Features carry their own tests and mobile acceptance.

| ID | Feature | Depends on | Acceptance |
|----|---------|------------|------------|
| T17a | Branch management | T16a, T16c, T16d | List/create/switch/rename/delete branches through mobile controls; tracking awareness, dirty-worktree checks, scoped destructive confirmations, and correct refresh after switching. |
| T17b | Tag management | T16c, T16d | List/create/delete lightweight and annotated tags; publish or delete remote tags explicitly; distinguish local changes from remote publication. |
| T17c | Selected-file restore | T16c | Restore selected files from index or a chosen commit; distinguish unstaging from discarding edits; preview affected scope, confirm destructive writes, and preserve unrelated files/child repositories. |

## Completion Criteria

- [ ] Branch workflows work independently in each repository on mobile.
- [ ] Tags can be managed locally and published explicitly to the chosen remote.
- [ ] Selected-file restore is clear, scoped, and preserves unrelated work.
- [ ] Every feature has focused automated coverage plus separately recorded installed Android/iOS acceptance under T10.
- [ ] Existing T16 operations remain correct while switching repositories or branches.

T16 includes merge resolution for divergent pulls; it does not depend on a full
branch-management UI. T17a adds the broader branch-management conveniences.
Stash, rebase, SSH, LFS, hooks, submodules, and linked worktrees are not implicitly
promised by this task; their assessed limits remain in the workflow document.
T4's existing revert refinement overlaps T17c: coordinate implementation and
cross-reference evidence rather than implementing two restore flows.
