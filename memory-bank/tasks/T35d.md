# T35d: Mobile and Remote Transport Reliability

*Last Updated: 2026-09-04 02:19:21 IST*

**Status**: 🔄 **IN PROGRESS**
**Priority**: HIGH
**Parent**: T35

## Scope

Unify Git and GitHub HTTP behavior and establish an evidence-based mobile
repository-size, pack-index, and transfer-progress support boundary.

## Acceptance Criteria

- [ ] Git smart HTTP and GitHub API calls use the supported native Obsidian
  transport consistently.
- [ ] Document that response chunking does not remove whole-response native
  buffering unless a genuinely streaming transport is available.
- [x] Define separate progress metrics for network bytes, Git objects, and
  checked-out files; never label object counts as byte counts.
- [ ] Provide live transferred bytes, total bytes when computable, rate, and
  ETA when the selected transport can support them; otherwise display an
  explicit indeterminate state.
- [x] Pass object-progress callbacks through every fetch/clone path, including
  the current shallow-fetch fallback.
- [x] Instrument checkout or provide an equivalent file-progress source for
  files written and total files.
- [ ] Decide and document the mobile pack-index strategy or limitation.
- [ ] Test large clone, pull, push, remote history, and commit expansion flows
  on Android and iOS.
- [ ] Record supported repository-size limits and failure guidance.

## Newly Recorded Progress-Metrics Issue — 2026-08-12

- `requestUrl` returns a fully buffered `arrayBuffer`; the current 64 KiB
  iterator only chunks an already completed response and cannot report live
  network bytes, total transfer size, rate, or ETA.
- The fallback `git.fetch` path passes `onMessage` but not `onProgress`, so the
  modal shown during the reported Android clone cannot display Git object
  counts.
- isomorphic-git progress values are object counts during pack processing, not
  byte counts. The current modal formats them as `B`/`KB`, which is incorrect.
- The modal's rate calculation subtracts the current byte total from itself,
  producing zero even if byte events were available.
- Checkout exposes no file-level progress callback, so file counts require
  explicit checkout instrumentation or a custom tree/write traversal.
- The requested terminal-style display therefore requires both transport-level
  telemetry and a distinct checkout-progress contract; it is not only a CSS
  change.

## Implementation Slice — 2026-08-12

- Git HTTP response consumption now reports loaded bytes, best-effort totals,
  and rate samples to the progress handle, while preserving cancellation checks
  between 64 KiB parser chunks.
- Fetch and clone paths pass isomorphic-git's object progress through to the
  modal. Object counts are displayed as objects, never as KB/MB.
- Checkout displays file counts from `Updating workdir` and accumulated vault
  write bytes from `ObsidianFsAdapter`.
- The modal now shows Objects, Data, Rate, ETA, Files, Written, phase status,
  and elapsed time in the requested terminal-style layout.
- The native transport limitation remains: `requestUrl` buffers the complete
  response, so the displayed byte metrics are response-consumption telemetry,
  not live wire-level transfer metrics. A genuinely streaming transport is
  still required to close the full acceptance criterion.

## Mobile Existing-Repository Ref Failure — 2026-09-03

- Real mobile testing of the existing non-empty `typora-notes` repository fails
  during index-repair dry run with `Could not find refs/heads/main`.
- This is a repository-state/ref-resolution issue, not evidence that the
  desktop index repair or remote comparison path is mobile-safe.
- Add device diagnostics for `HEAD`, local branch refs, remote-tracking refs,
  and adapter reads before implementing recovery.

## Session Continuation — 2026-09-03

- The plugin's mobile-sensitive repair and fingerprint paths now use bounded
  concurrency, but this requires real-device acceptance.
- isomorphic-git v1.41.9 was inspected as a possible upgrade baseline. Any
  upgrade or fork must be tested against the Obsidian adapter, pack metadata,
  mobile refs, and the existing `requestUrl` transport.
- T36 owns the independent dependency upgrade/fork decision.

## Reliability Follow-up Closeout — 2026-09-03

- Pull now compares local and remote object IDs and avoids an unnecessary
  merge/checkout when the repository is already current. Progress completion
  freezes elapsed time instead of continuing after the operation finishes.
- The push surface has operation-specific phases, but native `requestUrl`
  response buffering still prevents true wire-level transfer telemetry.
- Mobile acceptance remains open for refs, pack/index behavior, large
  operations, remote history, and real timing. T37 treats these adapter and
  transport boundaries as inputs to the rewrite assessment.

## Log Deduplication Fix — 2026-09-04

- Persistent log parsing now restores structured payloads from the existing
  file format before merging with live entries.
- The logger treats a live and persisted copy with matching level, namespace,
  message, payload, and only small timestamp drift as one event.
- This prevents the Log tab from displaying the same operation lifecycle record
  twice while preserving genuinely separate repeated status events.

## Log History Display Follow-up — 2026-09-04

- Persistent `debug.log` loading and live/file deduplication were already
  present; the remaining display defect was a view-only `slice(0, 50)` that
  hid older retained entries when the current session was busy.
- The sidebar now renders the full bounded set returned by the shared logger,
  including entries loaded from earlier plugin sessions. Entries written
  before persistent file logging existed cannot be reconstructed from source.
- The full automated package check passes; cross-session behavior still needs
  verification in a real Obsidian installation with an existing `debug.log`.

## Session Closeout Note — 2026-09-04

- Persistent logging and duplicate-event handling were addressed, but many
  remaining UI and runtime issues keep this task open.
