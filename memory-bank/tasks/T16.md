## Description

Extend Git Sync from one configured repository to a general Git interface for
repositories in any folder within the open vault. Users must be able to create,
clone, open, switch, inspect, commit, fetch, pull, push, and configure
remotes on mobile without a desktop or terminal dependency. The vault root is
an optional repository, not a required parent repository.

The user explicitly limited this plan to vault folders and requires full mobile
usability. Retain the JavaScript Git backend and vault DataAdapter. External
folders and native Git are outside this task. Ordinary nested repositories must
not be confused with Git submodules. Advanced backend gaps remain explicit;
this task does not promise arbitrary command-line Git parity.

## Subtasks

Subtasks follow user-facing features. All implementation is pending.

| ID | Feature | Depends on | Acceptance |
|----|---------|------------|------------|
| T16a | Repository management: create, discover, open, and switch | T2, T3 | Mobile repository selector; initialize empty/populated folders; save per-repository configuration; migrate existing settings; protect parent/child boundaries and preserve secrets. |
| T16b | Clone a repository into a vault folder | T16a | Choose destination and remote branch/default; optional shallow clone; correct credentials; progress and failed/interrupted-clone recovery; explicit filename compatibility results. |
| T16c | Changes, staging, commits, and history per repository | T16a | Existing local workflows work for each repository; isolated selection/history/cache/events/provider targets; packed-ref-aware inspection; actions and late results cannot affect a different selected repository. |
| T16d | Remote configuration and synchronization | T16a, T16c | Named remotes/upstreams and repository-specific auth; fetch/pull/push use captured targets and coordinated writes; preserve existing remote configuration; clear errors and scoped force confirmations. |
| T16e | Diverged histories and merge conflict resolution | T16c, T16d | Merge fetched/local refs; text/binary/delete-modify conflict decisions; correct merge parents; complete/abort and resume after reload without losing unrelated edits. |

Each feature includes its own automated checks, mobile controls, responsiveness,
interruption handling, and installed Android/iOS acceptance. Migration, state
isolation, integration changes, and performance are implementation requirements,
not standalone feature subtasks. T15 supplies test infrastructure and T10 records
platform acceptance. Advanced backend limits remain documented, not a catch-all
subtask. T17 tracks lower-priority branch/tag management and selected-file restore.

## Completion Criteria

- [ ] Multiple independent repositories work in vault subfolders, whether or not the vault root is a repository.
- [ ] Create/open/clone/switch, local changes/history, remote synchronization, and merge resolution are fully usable from mobile controls.
- [ ] Parent/child boundaries, settings migration, credential isolation, queued targets, stale reads, and provider targets are covered.
- [ ] Diverged histories can be merged and conflicts resolved, completed, or aborted on mobile with correct history.
- [ ] Interrupted operations and unsupported filenames produce actionable, repository-specific results.
- [ ] Capabilities and limitations are accurately visible; unsupported features cannot silently alter repository semantics.
- [ ] Automated, build, remote, Android, and iOS evidence is recorded separately; missing host checks remain open.
