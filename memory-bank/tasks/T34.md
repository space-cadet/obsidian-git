# T34: Remote Authentication for Obsidian Git

*Created: 2026-08-10 22:34:02 IST*
*Last Updated: 2026-08-10 22:34:02 IST*

**Status**: 🔄 **IN PROGRESS**
**Priority**: HIGH

## Scope

Provide a clear, safe authentication path for HTTPS Git remotes in Obsidian
Git. This task is separate from T29 release work: it owns authentication
diagnostics, future GitHub sign-in design, and mobile/desktop authentication
acceptance.

## Child Tasks

1. **T34a: PAT Validation and Repository-Access Diagnostics** — active
2. **T34b: GitHub Device-Flow Authentication** — planned after T34a
3. **T34c: Android/Desktop Authentication Acceptance Tests** — planned after
   the supported authentication path is available

## Current Evidence

- The Settings Test Connection action was changed to perform only a read-only
  Git smart-HTTP ref check. It no longer requires, clones, or initializes a
  local repository.
- Commit `22857f1` was pushed to `main`; Actions run `31021565574` succeeded,
  and the published `dev` ZIP contains the revised Test Connection code.
- Android testing reached the remote endpoint. The supplied fine-grained token
  returned HTTP 401 from both GitHub's account API and the Git smart-HTTP
  endpoint. This proves the observed failure is credential rejection, not a
  missing local repository or an outdated published bundle.
- The token supplied for diagnosis was treated as compromised and must be
  revoked. No token value is recorded here.

## Boundaries

- Preserve manual HTTPS username/PAT support for GitHub, GitLab, and other
  supported Git hosts.
- Do not record, log, commit, or display token values.
- Do not conflate a valid GitHub account token with access to a selected
  repository; diagnostics must identify the failing layer.
- SSH authentication remains a separate future decision.
